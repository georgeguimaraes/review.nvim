1. OVERVIEW                                                  *review-overview*

review.nvim adds code review comments to |codediff.nvim|. You add comments
(notes, suggestions, issues and praise) to lines in a diff. Then you export
the comments to the clipboard, or you send them to sidekick.nvim for an AI
chat.

Features:
- Comments on a line or on a range of lines, shown as boxes of virtual text
- Four comment types: Note, Suggestion, Issue and Praise
- One comment store for each repository, kept across restarts
- Notes on any file with `:Review note`, with no diff open
- A markdown export for AI chats
- A commit picker to review a revision range
- A branch picker, with an optional picker for the base
- A readonly mode and an edit mode, each with its own keymaps
- Files marked as reviewed, which `<Tab>` skips (|review-reviewed|)

==============================================================================
2. REQUIREMENTS                                          *review-requirements*

- Neovim >= 0.10
- codediff.nvim (https://github.com/esmuellert/codediff.nvim)
- nui.nvim (https://github.com/MunifTanjim/nui.nvim)

3. COMMANDS                                                 *review-commands*

All commands start with `:Review`.

                                                                     *:Review*
:Review                     Open the codediff view with the review keymaps.
                            The view shows the staged and unstaged changes.

:Review open                Same as `:Review`.

                                                             *:Review-commits*
:Review commits             Open the commit picker with the last 50 commits.
                            Use `<Space>` to select a range. Use `<CR>` to
                            confirm.

:Review commits {sha}       Review a single commit (diffs {sha}^ against
                            {sha}).

:Review commits {rev1} {rev2}
                            Review a revision range. This command does not
                            open the picker.

                                                              *:Review-branch*
:Review branch              Pick a branch to review. review.nvim finds the
                            base. When `branch.pick_base` is true, a second
                            picker opens for the base.

:Review branch {target} [{base}]
                            Review a branch. This command does not open a
                            picker. When you do not give {base}, the base is
                            `branch.base` or the base that review.nvim finds.

                                                               *:Review-close*
:Review close               Export the comments and close the review tab.
                            When `export.clear_on_close` is true (default),
                            review.nvim also archives and clears the
                            comments.

                                                              *:Review-export*
:Review export              Export the comments to the targets in
                            |review-config-export| and open a preview split.

                                                             *:Review-preview*
:Review preview             Show the export in a vertical split.

                                                            *:Review-sidekick*
:Review sidekick            Send the comments to sidekick.nvim.

                                                                *:Review-list*
:Review list                Show all comments in a picker. In a review, the
                            comment that you pick opens in the diff, at its
                            line, in the pane of its side. If the file is
                            not in the review, review.nvim shows a warning.
                            Outside a review, the file of the comment opens
                            at its line.

                                                               *:Review-clear*
:Review clear               Archive and clear all comments.

                                                              *:Review-toggle*
:Review toggle              Toggle between readonly mode and edit mode.

                                                                *:Review-note*
:Review note                Add a comment on the current line of a file in
                            the repository. You do not need a diff.

:'<,'>Review note           Add a comment on the selected lines.

                                                                *:Review-edit*
:Review edit                Edit the comment at the cursor, in a diff or in
                            a different buffer.

                                                              *:Review-delete*
:Review delete              Delete the comment at the cursor.

4. CONFIGURATION                                              *review-config*

Call `require("review").setup(opts)` with the options below. All the fields
are optional. The example shows the default values.
>lua
    require("review").setup({
      comment_types = {
        note = {
          key = "n",
          name = "Note",
          icon = "📝",
          hl = "ReviewNote",
          line_hl = "ReviewNoteLine",
        },
        suggestion = {
          key = "s",
          name = "Suggestion",
          icon = "💡",
          hl = "ReviewSuggestion",
          line_hl = "ReviewSuggestionLine",
        },
        issue = {
          key = "i",
          name = "Issue",
          icon = "⚠️",
          hl = "ReviewIssue",
          line_hl = "ReviewIssueLine",
        },
        praise = {
          key = "p",
          name = "Praise",
          icon = "✨",
          hl = "ReviewPraise",
          line_hl = "ReviewPraiseLine",
        },
      },

      codediff = {
        readonly = true,
      },

      branch = {
        base = nil,
        pick_base = false,
      },

      export = {
        -- header: four lines, see |review-config-export|
        clipboard = true,
        on_export = nil,
        clear_on_close = true,
      },

      keymaps = { ... },  -- see |review-keymaps|
    })
<

                                                     *review-config-codediff*
codediff.readonly ~
    When true (default), the diff buffers are read-only and single-key
    keymaps are active (for example, `i` adds a comment). When false, the
    leader-based keymaps are active. Press `R` to toggle the mode.

                                                       *review-config-branch*
branch.base ~
    The base for `:Review branch` when you do not give one. The base picker
    also puts the cursor on it. When nil (default), review.nvim uses
    `origin/HEAD`, then `main` or `master`.

branch.pick_base ~
    When true, `:Review branch` with no arguments opens a base picker after
    the target picker. The cursor starts on `branch.base` or on the base that
    review.nvim finds. Defaults to false. When you give {target}, no picker
    opens.

                                                        *review-config-export*
export.header ~
    The text at the top of every export. The default has four lines: an
    instruction, the comment types and the `~` legend. A custom header
    replaces all four lines. If the reader needs the comment types and the
    `~` legend, explain them in your header. See |review-export|.

export.clipboard ~
    When true (default), copy the export to the `+` and `*` registers.

export.on_export ~
    A `function(markdown, comments)` that runs on every export (`C`,
    `:Review export` and `q`). Use it to send the export to a tmux pane, a
    file or an agent. Defaults to nil.

export.clear_on_close ~
    When true (default), `q` and `:Review close` archive and clear the
    comments after the export. When false, the comments stay.

5. KEYMAPS                                                   *review-keymaps*

Use `opts.keymaps` to change the keymaps. To disable a keymap, set it to
`false`. The keymaps are local to the buffers of the review diff.

READONLY MODE (default)                              *review-keymaps-readonly*

These keymaps are active when `codediff.readonly = true`:

    Key     Description ~
    `i`       Add a comment (opens the type picker)   |n, x|
    `e`       Edit the comment at the cursor          |n|
    `d`       Delete the comment at the cursor        |n|
    `F`       Add a comment on the whole file         |n|
    `r`       Mark reviewed and go to the next file   |n|

EDIT MODE                                               *review-keymaps-edit*

These keymaps are active when `codediff.readonly = false`:

    Key           Description ~
    `<localleader>cc`    Add a comment (pick the type)       |n, x|
    `<localleader>cn`    Add a note                          |n, x|
    `<localleader>cs`    Add a suggestion                    |n, x|
    `<localleader>ci`    Add an issue                        |n, x|
    `<localleader>cp`    Add a praise                        |n, x|
    `<localleader>cf`    Add a comment on the whole file     |n|
    `<localleader>cr`    Mark the file as reviewed           |n|
    `<localleader>ce`    Edit the comment at the cursor      |n|
    `<localleader>cd`    Delete the comment at the cursor    |n|

NAVIGATION                                               *review-keymaps-nav*

    Key         Description ~
    `]n`          Next comment in the file              |n|
    `[n`          Previous comment in the file          |n|
    `<Tab>`       Next unreviewed file                  |n|
    `<S-Tab>`     Previous unreviewed file              |n|
    `]f` `[f`     Next or previous file (all files)     |n|
    `f`           Show or hide the file panel           |n|
    `c`           List all comments                     |n|

ACTIONS                                               *review-keymaps-actions*

    Key         Description ~
    `C`           Export to the clipboard and preview    |n|
    `S`           Send to sidekick.nvim                  |n|
    `<C-r>`       Archive and clear all comments         |n|
    `R`           Toggle readonly mode and edit mode     |n|
    `q`           Export and close the review            |n|
    `?`           Show the help popup                    |n|
    `t`           Toggle side-by-side and inline layout  |n|
    `g?`          Show the codediff help                 |n|

POPUP                                                 *review-keymaps-popup*

These keymaps are active in the comment popup. The comment box has the
`markdown` filetype. Thus, your markdown |FileType| autocommands and
ftplugins apply to it (for example, spell check).

    Key         Description ~
    `<C-s>`       Submit the comment                     |i, n|
    `<CR>`        Submit the comment (normal mode only)  |n|
    `q`           Cancel (normal mode)                   |n|
    `<Esc>`       Cancel (normal mode)                   |n|
    `<Tab>`       Go to the next comment type            |i, n|

6. HIGHLIGHT GROUPS                                      *review-highlights*

review.nvim defines these highlight groups with default links. To change
them, set them after you call setup() or in a |ColorScheme| autocommand.

  Group                   Default link      Usage ~
  `ReviewNote`              DiagnosticInfo    Note virtual text and sign
  `ReviewSuggestion`        DiagnosticHint    Suggestion virtual text and sign
  `ReviewIssue`             DiagnosticWarn    Issue virtual text and sign
  `ReviewPraise`            DiagnosticOk      Praise virtual text and sign
  `ReviewSign`              Comment           Sign column marker (●)
  `ReviewVirtText`          Comment           General virtual text
  `ReviewPickerHash`        Identifier        Commit hash in the picker
  `ReviewPickerMeta`        Comment           Author and date in the picker
  `ReviewPickerSelected`    String            Selected commit marker
  `ReviewReviewed`          DiagnosticOk      Check mark of a reviewed file

  Group                   Default bg        Usage ~
  `ReviewNoteLine`          #0d1f28           Note line background
  `ReviewSuggestionLine`    #152015           Suggestion line background
  `ReviewIssueLine`         #28250d           Issue line background
  `ReviewPraiseLine`        #15152a           Praise line background

7. EXPORT FORMAT                                              *review-export*

The export is a header and a numbered markdown list: >markdown
    I reviewed your code and have the following comments. Please address them.

    Comment types: ISSUE (problems to fix), SUGGESTION (improvements), NOTE (observations), PRAISE (positive feedback)
    Lines prefixed with ~ refer to the old (left) side of the diff.

    1. **[ISSUE]** `src/api.ts:23` - This endpoint does not handle errors
    2. **[SUGGESTION]** `src/utils.ts:~10-~14` - The old code was cleaner
    3. **[NOTE]** `README.md` - Add a section about the export
<
A `~` before a line number means the old (left) side of the diff. Ranges use
`start-end`. A comment with no line number is about the whole file. To change
the header, use `export.header` (|review-config-export|). To see the export
without a copy to the clipboard, use `:Review preview`.

==============================================================================
8. STORAGE                                                   *review-storage*

Each repository has one comment store. The store is a JSON file in: >
    stdpath("data")/review/{project-hash}.json
<
On Linux and macOS, stdpath("data") is usually `~/.local/share/nvim`. The
store keeps the comments across restarts. `:Review clear` moves the store to
`stdpath("data")/review/archive/` and starts an empty store. `q` and
`:Review close` do the same when `export.clear_on_close` is true. After 30
days, review.nvim deletes the archived files. The live store does not expire.

9. REVIEWED FILES                                           *review-reviewed*

When you finish a file, press `r` (`<localleader>cr` in edit mode). The file
gets a check mark in the file panel, and the review goes to the next
unreviewed file. Press `r` on a reviewed file to remove the mark. When all the
files are reviewed, `r` stays on the file and tells you.

`<Tab>` and `<S-Tab>` skip reviewed files. The codediff keymaps `]f` and `[f`
go to every file. When no file is marked, `<Tab>` works as before.

A mark is for the exact contents of both sides of the diff. review.nvim gets
the blob of each side from git. If one side changes, the mark no longer
applies. The check mark goes away at the next redraw of the file panel.

The marks are in `stdpath("data")/review/{project-hash}.reviewed.json`. `q`
(with `export.clear_on_close`) and `:Review clear` remove them with the
comments. `C` and `:Review export` keep them. The export does not include the
marks.
