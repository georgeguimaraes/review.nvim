1. OVERVIEW                                                  *review-overview*

review.nvim adds code review annotations on top of |codediff.nvim|. You can
leave comments (notes, suggestions, issues, praise) on specific lines in a
diff view, then export them to clipboard or send them to sidekick.nvim for AI
chat.

Features:
- Line and range comments with box-style virtual text
- Four comment types: Note, Suggestion, Issue, Praise
- Comments persist per repository across sessions
- Notes on any file with `:Review note`, no diff needed
- Export format optimized for AI conversations
- Commit picker to review specific revision ranges
- Branch picker with optional interactive base selection
- Readonly and edit modes with separate keymap sets

==============================================================================
2. REQUIREMENTS                                          *review-requirements*

- Neovim >= 0.10
- codediff.nvim (https://github.com/esmuellert/codediff.nvim)
- nui.nvim (https://github.com/MunifTanjim/nui.nvim)

3. COMMANDS                                                 *review-commands*

All commands use the `:Review` prefix.

                                                                     *:Review*
:Review                     Open codediff diff view with review keymaps.
                            Shows staged and unstaged changes.

:Review open                Same as `:Review`.

                                                             *:Review-commits*
:Review commits             Open commit picker (last 50 commits). Use
                            `<Space>` to select a range, `<CR>` to confirm.

:Review commits {sha}       Review a single commit (diffs {sha}^ against
                            {sha}).

:Review commits {rev1} {rev2}
                            Review a specific revision range directly,
                            skipping the picker.

                                                              *:Review-branch*
:Review branch              Pick a target branch to review. By default its
                            base is resolved automatically. When
                            `branch.pick_base` is true, a second picker opens
                            for the base branch.

:Review branch {target} [{base}]
                            Review a branch directly, skipping all pickers.
                            When {base} is omitted, use `branch.base` or the
                            detected default.

                                                               *:Review-close*
:Review close               Export comments and close the review tab. When
                            `export.clear_on_close` is true (default), the
                            comments are archived and cleared.

                                                              *:Review-export*
:Review export              Export comments (clipboard and
                            `export.on_export`) and open a preview split.

                                                             *:Review-preview*
:Review preview             Preview exported markdown in a vertical split.

                                                            *:Review-sidekick*
:Review sidekick            Send comments to sidekick.nvim.

                                                                *:Review-list*
:Review list                List all comments in a picker. In a review,
                            the picked comment opens in the diff, in the
                            pane of its side, at its line. Outside a review,
                            its file opens at its line.

                                                               *:Review-clear*
:Review clear               Archive and clear all comments.

                                                              *:Review-toggle*
:Review toggle              Toggle between readonly and edit mode.

                                                                *:Review-note*
:Review note                Add a comment on the current line of any file in
                            the repository. No diff needs to be open.

:'<,'>Review note           Add a comment on the selected lines.

                                                                *:Review-edit*
:Review edit                Edit the comment at the cursor, in a diff or in
                            any buffer.

                                                              *:Review-delete*
:Review delete              Delete the comment at the cursor.

4. CONFIGURATION                                              *review-config*

Call `require("review").setup(opts)` with any of the following options.
All fields are optional; defaults are shown.
>lua
    require("review").setup({
      comment_types = {
        note = {
          key = "n",
          name = "Note",
          icon = "📝",
          hl = "ReviewNote",
          line_hl = "ReviewNoteLine",
        },
        suggestion = {
          key = "s",
          name = "Suggestion",
          icon = "💡",
          hl = "ReviewSuggestion",
          line_hl = "ReviewSuggestionLine",
        },
        issue = {
          key = "i",
          name = "Issue",
          icon = "⚠️",
          hl = "ReviewIssue",
          line_hl = "ReviewIssueLine",
        },
        praise = {
          key = "p",
          name = "Praise",
          icon = "✨",
          hl = "ReviewPraise",
          line_hl = "ReviewPraiseLine",
        },
      },

      codediff = {
        readonly = true,
      },

      branch = {
        base = nil,
        pick_base = false,
      },

      export = {
        header = "...",  -- see |review-config-export|
        clipboard = true,
        on_export = nil,
        clear_on_close = true,
      },

      keymaps = { ... },  -- see |review-keymaps|
    })
<

                                                     *review-config-codediff*
codediff.readonly ~
    When true (default), diff buffers are readonly and simple single-key
    keymaps are active (e.g. `i` to add comment). When false, leader-based
    keymaps are used instead. Toggle at runtime with `R`.

                                                       *review-config-branch*
branch.base ~
    Automatic base used by `:Review branch` when it is not supplied. It is
    also initially highlighted in the base picker. When nil (default), use
    `origin/HEAD`, then `main` or `master`.

branch.pick_base ~
    When true, the no-argument `:Review branch` command opens a base picker
    after the target picker. `branch.base`, or the detected default, is
    initially highlighted. Defaults to false. Commands that supply {target}
    remain non-interactive.

                                                        *review-config-export*
export.header ~
    Text at the top of every export. The default has four lines: an
    instruction, the comment types and the `~` legend. A custom header
    replaces all four lines, so explain the comment types and `~` in it if
    the reader needs them. See |review-export|.

export.clipboard ~
    When true (default), copy the export to the `+` and `*` registers.

export.on_export ~
    `function(markdown, comments)` that runs on every export (`C`,
    `:Review export` and `q`). Use it to send the export to a tmux pane, a
    file or an agent. Defaults to nil.

export.clear_on_close ~
    When true (default), `q` and `:Review close` archive and clear the
    comments after the export. When false, the comments stay.

5. KEYMAPS                                                   *review-keymaps*

All keymaps can be customized via `opts.keymaps`. Set a key to `false` to
disable it. Keymaps are buffer-local to the review diff buffers.

READONLY MODE (default)                              *review-keymaps-readonly*

These keymaps are active when `codediff.readonly = true`:

    Key     Description ~
    `i`       Add comment (opens type picker)         |n, x|
    `e`       Edit comment at cursor                  |n|
    `d`       Delete comment at cursor                |n|
    `F`       Add file-level comment                  |n|

EDIT MODE                                               *review-keymaps-edit*

These keymaps are active when `codediff.readonly = false`:

    Key           Description ~
    `<localleader>cc`    Add comment (pick type)              |n, x|
    `<localleader>cn`    Add note                            |n, x|
    `<localleader>cs`    Add suggestion                      |n, x|
    `<localleader>ci`    Add issue                           |n, x|
    `<localleader>cp`    Add praise                          |n, x|
    `<localleader>cf`    Add file-level comment              |n|
    `<localleader>ce`    Edit comment at cursor              |n|
    `<localleader>cd`    Delete comment at cursor            |n|

NAVIGATION                                               *review-keymaps-nav*

    Key         Description ~
    `]n`          Next comment in file                  |n|
    `[n`          Previous comment in file              |n|
    `<Tab>`       Next file in explorer                 |n|
    `<S-Tab>`     Previous file in explorer             |n|
    `f`           Toggle file panel                     |n|
    `c`           List all comments                     |n|

ACTIONS                                               *review-keymaps-actions*

    Key         Description ~
    `C`           Export to clipboard + preview          |n|
    `S`           Send to sidekick.nvim                  |n|
    `<C-r>`       Clear all comments                     |n|
    `R`           Toggle readonly/edit mode               |n|
    `q`           Export & close review                   |n|
    `?`           Show help popup                         |n|
    `t`           Toggle layout (side-by-side/inline)     |n|
    `g?`          Show codediff help                      |n|

POPUP                                                 *review-keymaps-popup*

These keymaps are active inside the comment popup window. The comment box
has the `markdown` filetype, so your markdown |FileType| autocommands and
ftplugins (for example, spell check) apply to it.

    Key         Description ~
    `<C-s>`       Submit comment                         |i, n|
    `<CR>`        Submit comment (normal mode only)      |n|
    `q`           Cancel (normal mode)                   |n|
    `<Esc>`       Cancel (normal mode)                   |n|
    `<Tab>`       Cycle comment type                     |i, n|

6. HIGHLIGHT GROUPS                                      *review-highlights*

These highlight groups are defined with default links. Override them after
calling setup() or in a |ColorScheme| autocommand.

  Group                   Default link      Usage ~
  `ReviewNote`              DiagnosticInfo    Note virtual text and sign
  `ReviewSuggestion`        DiagnosticHint    Suggestion virtual text and sign
  `ReviewIssue`             DiagnosticWarn    Issue virtual text and sign
  `ReviewPraise`            DiagnosticOk      Praise virtual text and sign
  `ReviewSign`              Comment           Sign column marker (●)
  `ReviewVirtText`          Comment           General virtual text
  `ReviewPickerHash`        Identifier        Commit hash in picker
  `ReviewPickerMeta`        Comment           Author/date in picker
  `ReviewPickerSelected`    String            Selected commit marker

  Group                   Default bg        Usage ~
  `ReviewNoteLine`          #0d1f28           Note line background
  `ReviewSuggestionLine`    #152015           Suggestion line background
  `ReviewIssueLine`         #28250d           Issue line background
  `ReviewPraiseLine`        #15152a           Praise line background

7. EXPORT FORMAT                                              *review-export*

Comments are exported as a numbered markdown list after a header: >markdown
    I reviewed your code and have the following comments. Please address them.

    Comment types: ISSUE (problems to fix), SUGGESTION (improvements), NOTE (observations), PRAISE (positive feedback)
    Lines prefixed with ~ refer to the old (left) side of the diff.

    1. **[ISSUE]** `src/api.ts:23` - This endpoint does not handle errors
    2. **[SUGGESTION]** `src/utils.ts:~10-~14` - The old code was cleaner
    3. **[NOTE]** `README.md` - Add a section about the export
<
A `~` before a line number means the old (left) side of the diff. Ranges use
`start-end`. A comment with no line number is about the whole file. Change
the header with `export.header` (|review-config-export|). Use
`:Review preview` to see the export without copying it.

==============================================================================
8. STORAGE                                                   *review-storage*

Each repository has one comment store, a JSON file in: >
    stdpath("data")/review/{project-hash}.json
<
On Linux and macOS, stdpath("data") is usually `~/.local/share/nvim`. The
store keeps comments across restarts. `:Review clear` moves it to
`stdpath("data")/review/archive/` and starts an empty store. `q` and
`:Review close` do the same when `export.clear_on_close` is true. Archived
files are deleted after 30 days. The live store does not expire.
